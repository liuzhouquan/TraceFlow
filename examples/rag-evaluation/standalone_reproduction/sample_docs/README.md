# 示例资料

这组资料故意把事实拆到不同文件中，放入一篇包含大量“登录”关键词的干扰文档，还加入一份已经废弃、但与现行规则数字冲突的旧备忘。你可以用它检查：

- 语义问题是否能找到账号与令牌手册；
- 数字和时间是否能被准确引用；
- 一个问题是否能同时引用多份资料；
- 知识库没有答案时，系统是否会明确拒答。
- 系统是否能同时保留现行 `2%` 与旧版 `5%` 两条冲突证据。

界面中的“导入示例”会把 `01_` 到 `05_` 开头的 Markdown 文件加入待发布区；只有候选 Generation 通过质量门禁并切换 Milvus Alias 后，它们才成为 Serving 语料。推荐问题保存在 `sample_questions.json`，回答冒烟用的关键事实保存在 `expected_answers.json`，三种检索模式共享的离线对比集保存在 `retrieval_cases.json`，发布门禁使用 `../eval_cases/held_out_v1.jsonl`。
