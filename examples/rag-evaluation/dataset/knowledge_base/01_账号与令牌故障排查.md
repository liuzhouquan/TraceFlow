# 星河协作平台：账号与令牌故障排查

## 适用范围

本文用于处理星河协作平台 Web 端和移动端的登录态异常。平台使用两类令牌：Access Token 用于访问业务 API，有效期为 30 分钟；Refresh Token 用于换取新的 Access Token，有效期为 7 天。客户端不得把 Refresh Token 写入日志、埋点或错误上报正文。

## 收到 401 后如何恢复请求

业务请求收到 HTTP 401 时，客户端应该暂停继续发送需要登录态的请求，使用 Refresh Token 刷新一次 Access Token，然后只重试原请求一次。刷新成功后，等待队列中的其他请求可以继续执行。刷新接口本身返回 401，或者原请求重试后仍然返回 401，都必须清空本地登录态并引导用户重新登录，不能无限刷新和重试。

同一时刻有多个请求返回 401 时，只允许第一个请求发起刷新。其他请求进入等待队列，复用同一次刷新结果，避免并发刷新导致旧令牌覆盖新令牌。

HTTP 403 表示当前账号已经通过身份校验，但没有访问目标资源的权限。客户端遇到 403 时不能刷新令牌，应展示权限不足，并记录资源名称和请求追踪 ID。

## 人工排查步骤

值班工程师先查看网关返回的 `error_code`。`TOKEN_EXPIRED` 通常进入一次刷新流程；`TOKEN_REVOKED`、`ACCOUNT_DISABLED` 和 `REFRESH_TOKEN_EXPIRED` 必须重新登录。用户重新登录仍然失败时，再核对设备时间、账号状态和认证服务健康度。

排查过程中可以记录用户 ID 的脱敏值、请求追踪 ID 和错误码，但不能记录完整令牌。认证类 P1 故障要求值班工程师在 10 分钟内响应，并在 20 分钟内通知认证服务负责人。
